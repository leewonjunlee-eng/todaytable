# 1차 기반 구현 계획과 완료 판정

2026-10-16. 사용자가 승인한 기본 틀의 범위다. 설계·검증은 주 에이전트가 맡고 구현·수정은 Luna 모델에게 지시한다.

## 구현 범위

- Next.js·TypeScript 앱, PostgreSQL 영구 저장, 스키마 마이그레이션·명시적 초기 데이터 생성.
- 참가자·운영자 테스트 로그인, 서버 세션·로그아웃·역할과 소유권 검사.
- 신청서 기반 프로필·선호·식사 조건·동의 저장.
- 유효한 날짜·지역 복수 선택, 이용권 선택, 모의 결제, 본인 신청 상태 조회.
- 운영자 회차·식당 등록과 신청·결제 조회.
- 별도 Node 작업 프로세스, DB 예약 작업 획득·중복 방지·재시도·실행 이력.
- 크림·브라운 계열의 한국어 모바일 참가자 화면과 운영자 레이아웃.
- 환경변수 예시, 로컬 PostgreSQL 실행 구성, 실행·검증·배포 준비 안내.

매칭 엔진·테이블·채팅·환불·참석·피드백은 다음 구현 단계다. 지금 단계에서 완료된 것처럼 표시하지 않는다. 외부 유료 리소스 생성은 이번 기반 작업의 필수 완료 조건이 아니다.

## 검증할 사용자 흐름

1. 초기화한 DB에서 참가자·운영자 계정으로 로그인한다.
2. 참가자가 필수 프로필·동의를 저장하고 다시 조회한다.
3. 모집 중인 회차·지역을 고르고 이용권·모의 결제를 완료한다.
4. 중복 제출·재결제로 신청·승인·이용권이 중복 생성되지 않는다.
5. 참가자는 본인 신청만 볼 수 있고, 운영자 설정·조회 기능에 접근할 수 없다.
6. 운영자가 회차·식당을 추가하고 참가자 신청·결제를 조회한다.
7. 웹 브라우저 없이 별도 worker가 DB 예약 작업을 실행한다.
8. 서버와 worker를 재시작해 저장 내용과 미완료 작업이 유지·재개되는지 확인한다.
9. 실패 재시도·만료 점유 회수·작업 중복 실행을 확인한다.
10. 타입 검사·프로덕션 빌드와 핵심 업무 테스트를 통과한다.

## 검토 원칙

- 화면 동작이나 인메모리 모의 테스트만으로 PostgreSQL 영구 저장·동시 실행을 검증했다고 하지 않는다.
- 미설치 런타임·네트워크 제한 등으로 실행하지 못한 검증은 명시하고 가능한 준비를 계속한다.
- 기존 자료는 보존하며 원본 신청 데이터를 운영 계정·결제 완료 기록으로 임의 변환하지 않는다.
- 정책 임시값은 README에 근거와 함께 기록한다. 3회권 자동 갱신과 Instagram 필수 수집을 임의로 추가하지 않는다.
- 일정은 Asia/Seoul로 입력·표시하고 UTC로 저장한다. 식비와 참가비를 구분한다.
