## 수정한 실패와 동작

- 취소석 초대는 참가자의 응답을 기다립니다. 초대 수락 후 기존 식탁을 복구하고 종료된 대안 선택을 닫습니다. 응답을 기다리는 동안 자동 재배치하지 않습니다. 명시적으로 호출하는 기존 직접 복구 경로는 유지합니다. 초대가 정리된 3명+3명 식탁의 6명 병합을 실제 DB 테스트로 확인했습니다.
- 연결된 여러 회차의 매칭은 먼저 배치 가능한 해를 확보하고 제한된 탐색으로 배정 수·재배치 우선순위·품질을 비교합니다. 8명을 배정할 수 있는데 6명만 배정하던 반례를 해결했습니다. 적어도 4명을 모을 수 없는 잔여 후보를 탐색 상한에서 제외하여 정책별 조합 비교가 사라지던 문제도 해결했습니다.
- 19·25·50·100명 고정 사례는 전원 배정하고 정원·4~6명·차단 관계·중복 배정을 검사합니다. 이는 임의의 모든 입력에 대한 전역 최적해 보장이 아닙니다. 탐색 예산과 중단 이유를 기록합니다.
- 신청은 운영자가 등록한 모집 중·마감 전 회차에만 연결합니다. 기존 60일 달력에서 회차를 자동 생성하지 않습니다. 등록된 90일 뒤 회차도 신청할 수 있도록 신청·추천의 날짜 기준을 일치시켰습니다.
- 결제 실패·취소 상태는 새로고침 후 복구합니다. 이미 완료된 결제 대기 세션을 새 요청 키로 재사용해 중복 승인하는 경로를 차단하고 원래 요청의 재실행은 같은 결과를 반환합니다.
- PostgreSQL 028의 삭제 요청→문의 외래키를 실제 문의 ID 타입인 TEXT로 수정했습니다. 운영 미적용 마이그레이션의 오류를 복원 리허설 전에 수정했습니다.
- 새 신청·환불 알림에 맞게 기존 테스트가 확정 알림을 별도로 검사하도록 보완했습니다. 실제/구성 자료 분리가 도입된 분석 테스트는 명시적으로 전체 모드를 선택하고, 워커 검증은 고정 두 번 실행 대신 관련 대기 작업을 처리합니다.

## 마이그레이션과 보존

운영의 기존 001~020 뒤에 021~028을 추가합니다. 기존 열을 삭제하거나 원본 설문을 다시 가져오지 않습니다. 021은 기존 확정 식탁의 예약 업무만 초기화하고, 과거 자동/수동 확정 출처는 LEGACY로 남깁니다. 026은 운영자가 이미 선택한 기본 정책을 보존합니다.

운영 적용 전 public·provided_data의 66개 테이블 전체를 보호 파일로 백업했습니다. 별도 로컬 PostgreSQL DB에 이를 복원한 뒤 021~028을 적용하고 기존 열의 모든 원본 행을 대조했습니다. 기존 행 변경·누락은 없었으며 신규 정책 등의 추가 행은 구분했습니다. 리허설 근거는 `.data/completion-migration-rehearsal.json`입니다.

배포는 `/tmp/todaytable-completion-release`와 워커 전용 복사본의 허용된 소스만 업로드합니다. `.data`, 환경 파일, DB 백업, 원본 설문 파일·녹음·무관한 캡처는 포함하지 않습니다. 런타임 소스는 동일하고 워커의 서비스 설정에서만 HTTP 상태 검사를 제외합니다. 파일별 SHA-256은 `.data/completion-release-manifest.json`, `.data/completion-release-worker-manifest.json`에 남깁니다.
